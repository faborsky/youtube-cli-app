# YouTube CLI

Python CLI for managing YouTube videos via YouTube Data API v3 + reading performance via
YouTube Analytics API v2. Version 2.0.0 (`__version__` in `youtube_cli.py`, `--version` prints it).
Public repo: https://github.com/faborsky/youtube-cli-app

## Quick Start

```bash
source venv/bin/activate && python youtube_cli.py auth    # First time only
source venv/bin/activate && python youtube_cli.py <command>
```

## Structure

```
youtube_cli.py               # Main CLI (single file)
CHANGELOG.md                 # Keep a Changelog, SemVer
docs/api-notes.md            # How the APIs actually behave (view counting, quotas, gotchas)
.env                         # YOUTUBE_CLIENT_ID, YOUTUBE_CLIENT_SECRET

```

## Commands

| Command | Purpose | Key Flags |
|---------|---------|-----------|
| `auth` | One-time OAuth setup (opens browser) | -- |
| `videos` | List recent videos | `--limit`, `--json` |
| `video-get` | Get video details | `--video-id ID`, `--json` |
| `upload` | Upload video + metadata | `--file`, `--title`, `--description`, `--tags`, `--category`, `--privacy`, `--thumbnail`, `--playlist`, `--language`, `--publish-at`, `--json` |
| `video-update` | Update video metadata | `--video-id ID`, `--title`, `--description`, `--tags`, `--privacy`, `--thumbnail`, `--json` |
| `video-delete` | Delete video | `--video-id ID`, `--confirm` (required) |
| `stats` | Channel/video statistics (Data API) | `--video-id` (optional), `--engaged`, `--json` |
| `analytics` | Channel analytics — views, engagedViews, watch time, retention (averageViewPercentage), traffic sources, subs (YouTube Analytics API v2) | `--days`, `--start-date`/`--end-date`, `--dimensions day\|video\|insightTrafficSourceType\|creatorContentType`, `--sort`, `--video-id`, `--max-results`, `--json` |
| `playlists` | List playlists | `--json` |

> `analytics` and `stats --engaged` need the **YouTube Analytics API enabled** in the GCP project + scope `yt-analytics.readonly` (both done 2026-06-15). If either returns a scope error, run `auth` once to re-grant.

## View counting changed on 2026-08-24

YouTube unified view counting across **all** formats: a view counts the moment playback starts, no
minimum watch time (Shorts have worked this way since 2025-03-31).

- `viewCount` (Data API) and `views` (Analytics) = the **new** definition.
- `engagedViews` (Analytics) = the **old** definition — the only way to compare across that date.
  Bulk Reporting API calls it `engaged_views`.
- `analytics` requests `engagedViews` by default; `stats --engaged` adds lifetime engaged views.

**A jump in views around 2026-08-24 is a definition change, not growth.** Details and live-verified
numbers in [docs/api-notes.md](docs/api-notes.md).

## Safety

- Videos are uploaded as **private** by default.
- Delete requires `--confirm` flag.
- Credentials are in `.env` (never commit this file).
- OAuth token stored in home directory (`~/.youtube-cli-token.json`), not in project.

## API Notes

- Uses YouTube Data API v3 + YouTube Analytics API v2 via `google-api-python-client`.
- Auth: OAuth 2.0 Installed App flow. One-time browser consent, then auto-refresh via stored refresh token.
- Upload: Resumable upload with chunked transfer (~12.5 MB chunks) and exponential backoff retry.
- `video-update` fetches current data first, then merges changes (YouTube API requires full snippet on update).
- Thumbnail upload is a separate API call after video upload; failures are non-fatal.
- Default quota: 10,000 units/day. Upload ~1,600 units, `search.list` 100, read 1, write 50.
- Analytics data is despammed and lags ~1–2 days, so it never matches Data API `viewCount` exactly.
- The Analytics API serves only **fixed dimension/metric combinations**. `analytics` therefore adapts
  what the user left unspecified — narrows default metrics for core-only dimensions, adds the
  mandatory `sort`/`maxResults` for top-N dimensions, snaps `month` to month-aligned dates — and
  reports each adjustment on stderr. Explicit flags always win. Full table in
  [docs/api-notes.md](docs/api-notes.md).

Full detail: [docs/api-notes.md](docs/api-notes.md).

## Conventions

- All commands support `--json` for machine-readable output — and it must be **the only thing on
  stdout** (this was broken in `videos`/`playlists` until 2.0.0: a human summary line trailed the
  JSON payload and broke every parser).
- The CLI exits with code 1 on errors and prints errors to stderr.
- Progress messages and warnings go to stderr, results to stdout.
- Optional enrichment (e.g. `stats --engaged`) degrades gracefully: warn on stderr, still print the
  primary result.

## Release checklist

Bump `__version__` in `youtube_cli.py` → update `README.md` + `README.cs.md` (version line, command tables, new flags),
this file (command table + anything factual that changed), `CHANGELOG.md` (new

commands you touched against the live API, including `--json` validity → commit → tag `vX.Y.Z` →

notes = the CHANGELOG entry). A pushed tag alone does not show on /releases.
